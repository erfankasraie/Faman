# Introduction

`last` تاریخچه login/logout کاربران به سیستم را از فایل `/var/log/wtmp` نمایش می‌دهد؛ برای بررسی‌های امنیتی («چه کسی و چه زمانی وارد سیستم شده») و عیب‌یابی بسیار مفید است.

# Syntax

```
last [OPTIONS] [USERNAME]
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-n N` | نمایش فقط N رکورد آخر |
| `-a` | نمایش نام هاست در ستون آخر (خواناتر) |
| `-x` | نمایش رویدادهای shutdown/runlevel هم |
| `-f FILE` | خواندن از یک فایل log مشخص به‌جای پیش‌فرض |

# Examples

```bash
# نمایش کامل تاریخچه login
last

# فقط ۱۰ ورود آخر
last -n 10

# بررسی تاریخچه login یک کاربر خاص
last ali

# نمایش با فرمت خواناتر شامل نام هاست
last -a

# بررسی تاریخچه ری‌استارت/خاموشی سیستم
last reboot

# بررسی تلاش‌های ورود ناموفق (نیازمند دسترسی root، فایل جدا)
sudo lastb
```

# Common mistakes

- گیج‌شدن `last` (ورودهای موفق) با `lastb` (تلاش‌های ورود **ناموفق** — نیاز به دسترسی root دارد و از فایل جداگانه `/var/log/btmp` می‌خواند).
- اعتمادکامل به `last` برای بررسی امنیتی بدون توجه به این‌که فایل‌های log می‌توانند توسط مهاجم با دسترسی root پاک یا دستکاری شوند؛ برای امنیت جدی، لاگ‌های مرکزی (SIEM) قابل‌اعتمادتر هستند.

# Tips

- `last reboot` روش سریعی برای دیدن تاریخچه ری‌استارت‌های سیستم است.
- برای عیب‌یابی «چرا سرور ناگهان ری‌استارت شد»، ترکیب `last reboot` با `journalctl -b -1` (لاگ‌های قبل از آخرین بوت) اطلاعات کاملی می‌دهد.

# Related commands

- `lastb` — تلاش‌های ورود ناموفق
- `who` — کاربران فعلاً login شده
- `journalctl` — لاگ‌های کامل‌تر سیستم‌دی
- `uptime` — مدت زمان روشن‌بودن فعلی سیستم
