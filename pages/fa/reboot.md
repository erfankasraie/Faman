# Introduction

`reboot` سیستم را دوباره راه‌اندازی می‌کند. روی اکثر سیستم‌های مدرن این دستور در واقع یک درخواست به `systemd` است (نه ری‌استارت مستقیم سخت‌افزاری)، بنابراین قبل از خاموشی، سرویس‌ها به‌درستی متوقف می‌شوند.

⚠️ روی یک سرور راه دور (SSH)، اجرای `reboot` بلافاصله اتصال شما را قطع می‌کند؛ مطمئن شوید راهی برای اتصال مجدد (مثل کنسول مدیریتی سرور) دارید.

# Syntax

```
reboot [OPTIONS]
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-f` | ری‌استارت اجباری و فوری (بدون خاموش‌کردن مرتب سرویس‌ها) |
| `-n` | بدون sync کردن دیسک قبل از ری‌استارت (خطرناک) |

# Examples

```bash
# ری‌استارت مرتب سیستم (نیاز به sudo)
sudo reboot

# زمان‌بندی ری‌استارت برای ۱۰ دقیقه بعد
sudo shutdown -r +10

# ری‌استارت فوری بدون توقف مرتب سرویس‌ها (فقط در شرایط اضطراری)
sudo reboot -f

# لغو یک ری‌استارت زمان‌بندی‌شده
sudo shutdown -c
```

# Common mistakes

- اجرای `reboot` روی یک سرور production بدون هماهنگی یا اطلاع‌رسانی که باعث قطعی ناگهانی سرویس می‌شود؛ برای این موارد `shutdown -r +N` با پیام هشدار به کاربران دیگر بهتر است.
- استفاده از `reboot -f` به‌طور عادی؛ این گزینه سرویس‌ها را به‌درستی متوقف نمی‌کند و می‌تواند باعث از‌دست‌رفتن داده شود؛ فقط برای مواقعی که سیستم قفل شده استفاده شود.

# Tips

- برای اطلاع‌رسانی به کاربران دیگر قبل از ری‌استارت، `shutdown -r +5 "سیستم تا ۵ دقیقه دیگر ری‌استارت می‌شود"` مناسب‌تر از `reboot` مستقیم است.
- بعد از هر ری‌استارت روی یک سرور، `journalctl -b` (لاگ‌های همان بوت جدید) برای بررسی سلامت راه‌اندازی مفید است.

# Related commands

- `shutdown` — خاموش‌کردن یا ری‌استارت با زمان‌بندی و پیام هشدار
- `systemctl reboot` — معادل مدرن از طریق systemd
- `uptime` — بررسی مدت زمان روشن‌بودن سیستم
- `last reboot` — تاریخچه ری‌استارت‌های قبلی
