# Introduction

`file` نوع واقعی یک فایل را بر اساس **محتوای** آن تشخیص می‌دهد (نه فقط پسوند نام فایل)؛ مثلاً می‌تواند بگوید یک فایل بدون پسوند در واقع یک تصویر PNG، آرشیو ZIP، یا اسکریپت شل است.

برای مبتدیان: پسوند فایل (مثل `.txt` یا `.jpg`) فقط یک قرارداد است و می‌تواند اشتباه یا گمراه‌کننده باشد؛ `file` محتوای واقعی را بررسی می‌کند.

# Syntax

```
file [OPTIONS] FILE...
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-b` | نمایش نتیجه بدون نام فایل (brief) |
| `-i` | نمایش نوع MIME استاندارد |
| `-z` | بررسی داخل فایل‌های فشرده هم |
| `-L` | دنبال‌کردن لینک نمادین و بررسی مقصد آن |

# Examples

```bash
# تشخیص نوع یک فایل
file document.pdf

# تشخیص نوع MIME (برای استفاده در اسکریپت یا وب)
file -i image.jpg

# بررسی یک فایل بدون پسوند
file mystery_file

# تشخیص نوع بدون نمایش نام فایل (برای اسکریپت‌نویسی)
file -b unknown_file

# بررسی تمام فایل‌های یک پوشه
file *

# بررسی این‌که آیا فایل واقعاً اجرایی است یا نه
file ./suspicious_script.sh
```

# Common mistakes

- اعتمادکردن صرف به پسوند فایل برای تشخیص نوع آن؛ یک فایل مخرب می‌تواند با پسوند `.jpg` در واقع یک اسکریپت باشد — `file` این را نشان می‌دهد.
- تصور اینکه `file` محتوای متنی فایل را می‌خواند یا تفسیر می‌کند؛ فقط ساختار و هدر فایل را بررسی می‌کند (مثلاً magic bytes).

# Tips

- برای بررسی امنیتی سریع یک فایل دانلودشده قبل از اجرا، همیشه `file` را قبل از باز کردن اجرا کنید.
- در اسکریپت‌های آپلود فایل، `file -i` (نوع MIME) قابل‌اعتمادتر از اعتماد به پسوند ارسالی کاربر است.

# Related commands

- `stat` — اطلاعات متادیتای فایل (اندازه، زمان تغییر، مجوز)
- `xxd` / `hexdump` — نمایش محتوای خام باینری فایل
- `mimetype` — ابزار مشابه برای تشخیص نوع MIME
