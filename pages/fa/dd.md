# Introduction

`dd` داده‌ها را به‌صورت خام (bit-by-bit) از یک منبع به یک مقصد کپی می‌کند؛ معمولاً برای ساخت فلش‌های بوت‌ابل، بکاپ‌گیری کامل از دیسک یا پارتیشن، و تست سرعت دیسک استفاده می‌شود.

⚠️ **هشدار مهم:** `dd` می‌تواند به‌سادگی و بدون هیچ تأییدی محتوای یک دیسک را کاملاً پاک کند. همیشه مسیر `of=` (خروجی) را دوبار بررسی کنید.

# Syntax

```
dd if=SOURCE of=DESTINATION [OPTIONS]
```

# Options

| گزینه | توضیح |
|-------|--------|
| `if=` | فایل یا دستگاه ورودی (input file) |
| `of=` | فایل یا دستگاه خروجی (output file) |
| `bs=` | اندازه بلوک کپی (مثلاً `4M`) |
| `status=progress` | نمایش پیشرفت کپی |
| `conv=fsync` | اطمینان از نوشته‌شدن کامل داده روی دیسک |

# Examples

```bash
# ساخت فلش بوت‌ابل از فایل ISO (⚠️ ابتدا مسیر of را با lsblk تأیید کنید)
sudo dd if=ubuntu.iso of=/dev/sdb bs=4M status=progress conv=fsync

# بکاپ کامل از یک پارتیشن به یک فایل
sudo dd if=/dev/sda1 of=backup.img bs=4M status=progress

# ساخت یک فایل خالی به اندازه مشخص (برای تست یا swap)
dd if=/dev/zero of=testfile.img bs=1M count=100

# تست سرعت نوشتن دیسک
dd if=/dev/zero of=speedtest bs=1M count=1000 status=progress && rm speedtest
```

# Common mistakes

- ⚠️ اشتباه‌گرفتن `if=` و `of=` که باعث پاک‌شدن منبع به‌جای مقصد می‌شود.
- ⚠️ اشتباه‌نوشتن نام دستگاه خروجی (مثلاً `/dev/sda` به‌جای `/dev/sdb`) که می‌تواند دیسک اصلی سیستم را نابود کند — همیشه با `lsblk` یا `fdisk -l` مسیر را تأیید کنید.
- فراموش‌کردن `status=progress` و فکرکردن که برنامه هنگ کرده؛ `dd` به‌صورت پیش‌فرض هیچ خروجی نمایش نمی‌دهد.
- استفاده از `bs=512` (پیش‌فرض) که بسیار کند است؛ برای سرعت بهتر از `bs=4M` یا `bs=1M` استفاده کنید.

# Tips

- قبل از هر عملیات مخرب، دستگاه‌های متصل را با `lsblk` یا `sudo fdisk -l` بررسی کنید.
- بعد از اتمام کپی روی یک دستگاه فیزیکی، دستور `sync` را هم اجرا کنید تا مطمئن شوید همه داده‌ها واقعاً نوشته شده‌اند.
- برای ساخت فلش بوت‌ابل، ابزارهای امن‌تری مثل `balenaEtcher` هم وجود دارند که ریسک اشتباه را کاهش می‌دهند.

# Related commands

- `lsblk` — لیست دیسک‌ها و پارتیشن‌ها (برای پیداکردن نام درست دستگاه)
- `sync` — نوشتن اجباری بافرها روی دیسک
- `mount` / `umount` — سوارکردن و جداکردن فایل‌سیستم‌ها
- `rsync` — کپی فایل‌محور و امن‌تر (نه bit-by-bit)
