# Introduction

`nc` (netcat) یک ابزار همه‌کاره شبکه است که می‌تواند داده را از طریق TCP/UDP بخواند و بنویسد؛ اغلب برای تست اتصال به یک پورت، انتقال ساده فایل، یا دیباگ سرویس‌های شبکه استفاده می‌شود — به آن «چاقوی ارتش سوئیسی شبکه» هم می‌گویند.

# Syntax

```
nc [OPTIONS] HOST PORT
nc -l [OPTIONS] PORT
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-l` | حالت گوش‌دادن (listen) به‌جای اتصال به یک هاست |
| `-v` | نمایش جزئیات اتصال (verbose) |
| `-z` | فقط بررسی باز‌بودن پورت، بدون ارسال داده (اسکن سریع) |
| `-u` | استفاده از UDP به‌جای TCP |
| `-w SEC` | تایم‌اوت اتصال |

# Examples

```bash
# بررسی این‌که آیا یک پورت روی یک سرور باز است
nc -zv example.com 443

# اتصال ساده برای تست دستی یک پروتکل متنی (مثل HTTP)
nc example.com 80
# سپس تایپ کنید: GET / HTTP/1.1

# راه‌اندازی یک سرور ساده گوش‌دهنده برای تست
nc -l 8080

# انتقال یک فایل بین دو سیستم (روی گیرنده)
nc -l 9000 > received_file.txt
# روی فرستنده:
nc receiver_ip 9000 < myfile.txt

# اسکن سریع چند پورت رایج روی یک هاست
nc -zv example.com 22 80 443
```

# Common mistakes

- استفاده از `nc` برای انتقال فایل حساس بدون رمزنگاری؛ داده به‌صورت کاملاً خام (plain text) منتقل می‌شود — برای انتقال امن از `scp`/`rsync -e ssh` استفاده کنید.
- گیج‌شدن بین نسخه‌های مختلف netcat (OpenBSD nc در برابر GNU/traditional nc) که برخی گزینه‌ها (مثل `-e` برای اجرای دستور) فقط در بعضی نسخه‌ها موجود است.

# Tips

- `nc -zv` سریع‌ترین راه برای تست دستی «آیا فایروال این پورت را باز گذاشته» بدون نیاز به ابزار پیچیده‌تر است.
- برای تست دستی پروتکل‌های متنی ساده (مثل HTTP یا SMTP)، اتصال مستقیم با `nc` و تایپ دستی دستورات پروتکل روش خوبی برای یادگیری و دیباگ است.

# Related commands

- `ss` / `netstat` — بررسی پورت‌های باز محلی (نه اتصال به هاست دیگر)
- `curl` — تست HTTP سطح بالاتر (نه سطح خام سوکت)
- `scp` / `rsync` — انتقال امن و رمزنگاری‌شده فایل
- `telnet` — ابزار قدیمی‌تر مشابه برای تست اتصال متنی
