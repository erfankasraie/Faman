# Introduction

`shred` محتوای یک فایل را چندین بار با داده‌های تصادفی بازنویسی می‌کند تا بازیابی آن (recovery) بسیار سخت یا غیرممکن شود؛ برخلاف `rm` که فقط ورودی فایل را از فهرست حذف می‌کند و داده واقعی روی دیسک باقی می‌ماند.

# Syntax

```
shred [OPTIONS] FILE...
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-n N` | تعداد دفعات بازنویسی (پیش‌فرض ۳) |
| `-u` | حذف فایل هم پس از shred کردن (مثل rm) |
| `-z` | پاس نهایی با صفر برای پنهان‌کردن ردپای shred |
| `-v` | نمایش پیشرفت |

# Examples

```bash
# پاک‌سازی امن یک فایل حساس و سپس حذف آن
shred -uvz secret.txt

# بازنویسی ۷ بار برای امنیت بیشتر
shred -n 7 -u passwords.txt

# فقط بازنویسی بدون حذف نهایی (فایل خالی باقی می‌ماند)
shred important.doc
```

# Common mistakes

- ⚠️ استفاده از `shred` روی فایل‌سیستم‌های **SSD** یا فایل‌سیستم‌های copy-on-write (مثل Btrfs، ZFS)؛ در این موارد به‌خاطر wear-leveling و اسنپ‌شات‌ها، shred تضمینی برای پاک‌سازی واقعی نمی‌دهد.
- تصور اینکه `shred` روی یک فایل در فضای ابری یا بکاپ‌شده هم اثر دارد؛ نسخه‌های دیگر فایل (بکاپ، اسنپ‌شات، cache) دست‌نخورده باقی می‌مانند.
- فراموش‌کردن `-u`؛ بدون آن، فایل با محتوای بی‌معنی باقی می‌ماند ولی حذف نمی‌شود.

# Tips

- برای دیسک‌های SSD یا NVMe، بهتر است از ابزارهای رمزنگاری کامل دیسک (مثل LUKS) از ابتدا استفاده کنید تا نیازی به shred نباشد.
- برای پاک‌سازی کامل یک دیسک (نه فقط یک فایل)، می‌توان `shred` را مستقیم روی دستگاه اجرا کرد (مثلاً `/dev/sdb`) — بسیار خطرناک، دو بار مسیر را چک کنید.

# Related commands

- `rm` — حذف عادی (بدون بازنویسی امن)
- `dd` — می‌تواند برای بازنویسی دستی دیسک هم استفاده شود
- `wipe` — ابزار مشابه shred در برخی توزیع‌ها
