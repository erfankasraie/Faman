# Introduction

`base64` داده باینری (مثل تصویر یا فایل رمزنگاری‌شده) را به یک رشته متنی امن برای انتقال (فقط حروف/اعداد/چند نماد خاص) تبدیل می‌کند، یا برعکس آن را رمزگشایی می‌کند. کاربرد رایج: جاسازی تصویر در HTML/CSS، انتقال داده باینری در JSON، یا ذخیره کلیدها/گواهی‌ها در فرمت متنی.

⚠️ base64 **رمزنگاری نیست** — فقط یک روش کدگذاری (encoding) است و هیچ امنیتی فراهم نمی‌کند؛ هرکسی می‌تواند آن را به‌سادگی decode کند.

# Syntax

```
base64 [OPTIONS] [FILE]
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-d` | رمزگشایی (decode) به‌جای کدگذاری |
| `-w N` | شکستن خط در هر N کاراکتر (پیش‌فرض ۷۶؛ `0` یعنی بدون شکستن) |

# Examples

```bash
# کدگذاری یک فایل به base64
base64 file.png > file.b64

# کدگذاری بدون شکستن خط (یک خط پیوسته، مناسب برای JSON)
base64 -w 0 file.png

# رمزگشایی یک رشته base64 به فایل اصلی
base64 -d file.b64 > file_restored.png

# کدگذاری مستقیم یک رشته متنی
echo -n "سلام دنیا" | base64

# رمزگشایی یک رشته base64
echo "c2FsYW0=" | base64 -d
```

# Common mistakes

- تصور اینکه base64 نوعی رمزنگاری امن است؛ هرکسی بدون هیچ رمز عبوری می‌تواند آن را decode کند — فقط برای **کدگذاری** داده باینری به متن استفاده می‌شود، نه محافظت از آن.
- فراموش‌کردن `-w 0` هنگام نیاز به یک رشته یک‌خطی (مثلاً برای قراردادن در متغیر محیطی یا JSON) که باعث خطای فرمت می‌شود.

# Tips

- برای جاسازی مستقیم تصویر کوچک در HTML/CSS: `data:image/png;base64,$(base64 -w 0 image.png)`
- اگر می‌خواهید داده را واقعاً محافظت کنید (نه فقط کدگذاری کنید)، از `gpg` یا `openssl enc` استفاده کنید، نه base64.

# Related commands

- `openssl` — رمزنگاری واقعی (base64 معمولاً بعد از رمزنگاری برای نمایش متنی نتیجه استفاده می‌شود)
- `xxd` — نمایش hex باینری (نوع دیگری از نمایش داده خام)
- `gpg` — رمزنگاری و امضای واقعی فایل
