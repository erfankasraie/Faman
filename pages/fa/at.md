# Introduction

`at` یک دستور را برای اجرای **یک‌باره** در یک زمان مشخص در آینده زمان‌بندی می‌کند؛ برخلاف `crontab` که برای اجراهای تکرارشونده استفاده می‌شود.

برای مبتدیان: اگر می‌خواهید یک بار، مثلاً امشب ساعت ۲، یک اسکریپت اجرا شود، `at` مناسب‌تر از `cron` است.

# Syntax

```
at TIME
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-f FILE` | خواندن دستورات از یک فایل |
| `-l` | لیست کارهای زمان‌بندی‌شده (معادل `atq`) |
| `-r JOBID` | حذف یک کار زمان‌بندی‌شده (معادل `atrm`) |
| `-m` | ارسال ایمیل پس از اجرا حتی اگر خروجی نداشته باشد |

# Examples

```bash
# زمان‌بندی برای ساعت ۲۲:۰۰ امشب (سپس دستورات را تایپ کرده و Ctrl+D بزنید)
at 22:00
at> ./backup.sh
at> <Ctrl+D>

# زمان‌بندی با عبارت طبیعی
at now + 30 minutes
at teatime tomorrow

# اجرای دستورات از یک فایل
at 09:00 tomorrow -f script.sh

# دیدن لیست کارهای در صف
atq

# حذف یک کار با شماره
atrm 3
```

# Common mistakes

- فراموش‌کردن این‌که سرویس `atd` باید فعال و در حال اجرا باشد.
- تصور اینکه `at` مثل `cron` تکرار می‌شود؛ در واقع فقط یک‌بار اجرا می‌کند.
- عدم بررسی خروجی؛ نتیجه اجرا (در صورت نبود `-m` یا redirect) از طریق ایمیل محلی کاربر فرستاده می‌شود که معمولاً کسی چک نمی‌کند.

# Tips

- برای دیدن دقیق خروجی، در اسکریپت خودتان خروجی را به یک فایل لاگ هدایت کنید: `./script.sh > /tmp/out.log 2>&1`
- در بسیاری از توزیع‌ها باید جداگانه نصب شود: `apt install at`

# Related commands

- `crontab` — زمان‌بندی کارهای تکرارشونده
- `systemctl` — می‌توان با systemd timers هم زمان‌بندی کرد
- `nohup` — اجرای یک دستور که با بستن ترمینال متوقف نشود
