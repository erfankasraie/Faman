# Introduction

`source` (یا معادل کوتاه‌ترش `.`) یک فایل اسکریپت را در **همان** نشست پوسته فعلی اجرا می‌کند، نه در یک زیرفرآیند (subshell) جدید. این یعنی هر متغیر، function یا alias که در فایل تعریف شود، در پوسته جاری شما هم باقی می‌ماند — برخلاف اجرای عادی یک اسکریپت (`./script.sh`) که در یک فرایند جداگانه اجرا می‌شود و تغییراتش با پایان اسکریپت از بین می‌رود.

# Syntax

```
source FILE
. FILE
```

# Options

`source` گزینه ندارد؛ فقط یک مسیر فایل می‌گیرد و آن را در پوسته جاری اجرا می‌کند.

# Examples

```bash
# اعمال تغییرات فایل تنظیمات پوسته بدون بستن ترمینال
source ~/.bashrc

# فرم کوتاه (معادل دقیق source، استاندارد POSIX)
. ~/.bashrc

# بارگذاری متغیرهای محیطی از یک فایل .env در نشست جاری
source .env

# فعال‌سازی یک محیط مجازی پایتون (که خودش یک اسکریپت source-شونده است)
source myenv/bin/activate

# تعریف یک تابع کمکی در فایلی جدا و بارگذاری آن در اسکریپت اصلی
source ./helpers.sh
```

# Common mistakes

- اجرای فایل تنظیمات با `./script.sh` به‌جای `source script.sh`؛ در حالت اول، متغیرها و function های تعریف‌شده در پوسته فرزند باقی می‌مانند و بعد از پایان اسکریپت گم می‌شوند — نتیجه دلخواه (تغییر پوسته جاری) حاصل نمی‌شود.
- فراموش‌کردن `source ~/.bashrc` بعد از ویرایش فایل تنظیمات و تعجب از این‌که چرا تغییرات اعمال نشده.

# Tips

- اگر یک اسکریپت قرار است متغیر محیطی تنظیم کند یا پوسته جاری شما را تغییر دهد (مثل فعال‌سازی venv)، همیشه باید با `source` اجرا شود، نه به‌صورت مستقیم.
- `.` (نقطه) دقیقاً همان کار `source` را انجام می‌دهد و در اسکریپت‌های POSIX-سازگار (مثل `sh`) رایج‌تر است.

# Related commands

- `export` — تعریف متغیر محیطی که به فرایندهای فرزند هم منتقل شود
- `bash` — اجرای یک اسکریپت در زیرفرآیند جدید (برخلاف source)
- `exec` — جایگزین‌کردن کامل پوسته فعلی با یک فرمان دیگر
