# Introduction

`strace` تمام فراخوانی‌های سیستمی (system calls) یک برنامه را ردیابی و چاپ می‌کند. این ابزار برای دیباگ‌کردن این‌که یک برنامه چرا کند است، به کدام فایل‌ها دسترسی پیدا می‌کند، یا چرا کرش می‌کند فوق‌العاده مفید است.

برای مبتدیان: اگر یک برنامه بدون پیغام خطای مشخص کار نمی‌کند، `strace` نشان می‌دهد دقیقاً در چه مرحله‌ای (باز کردن فایل، اتصال شبکه، ...) گیر کرده.

# Syntax

```
strace [OPTIONS] COMMAND [ARGS...]
strace -p PID
```

# Options

| گزینه | توضیح |
|-------|--------|
| `-f` | ردیابی پردازش‌های فرزند (fork شده) هم |
| `-e trace=SET` | فقط دسته‌ای خاص از syscallها (مثلاً `open,read`) |
| `-o FILE` | ذخیره خروجی در فایل به‌جای صفحه |
| `-c` | خلاصه آماری از تعداد و زمان هر syscall |
| `-p PID` | اتصال به پردازش در حال اجرا |
| `-T` | نمایش زمان صرف‌شده برای هر syscall |

# Examples

```bash
# ردیابی کامل یک برنامه هنگام اجرا
strace ls

# فقط syscallهای مربوط به فایل
strace -e trace=open,read,write cat file.txt

# اتصال به یک پردازش در حال اجرا با PID
sudo strace -p 4821

# ذخیره خروجی در فایل برای بررسی بعدی
strace -f -o trace.log ./myapp

# خلاصه آماری از عملکرد syscallها
strace -c ./myapp
```

# Common mistakes

- اجرای `strace` روی یک سرویس در حال کار در محیط تولید بدون آگاهی از این‌که این ابزار برنامه را به‌شدت کند می‌کند.
- فراموش‌کردن `-f` وقتی برنامه پردازش‌های فرزند تولید می‌کند و در نتیجه از‌دست‌دادن اطلاعات مهم.
- نیاز به دسترسی `sudo` برای اتصال به پردازش‌های متعلق به کاربر دیگر.

# Tips

- برای پیدا کردن این‌که یک برنامه دنبال کدام فایل تنظیمات (config) می‌گردد: `strace -e trace=open,openat COMMAND 2>&1 | grep -i conf`
- خروجی `strace -c` برای پیداکردن این‌که کدام syscall بیشترین زمان را می‌گیرد بسیار خوب است.

# Related commands

- `ltrace` — ردیابی فراخوانی توابع کتابخانه‌ای (به‌جای syscall)
- `ps` — لیست پردازش‌ها
- `lsof` — فایل‌های باز‌شده توسط یک پردازش
- `dmesg` — لاگ کرنل
